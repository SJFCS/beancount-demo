# 账单导入

页面位于账本侧栏的「账单导入」，本地地址为：

`http://localhost:5173/ledger/local/private/plugins/payments`

首次更新后重启 `ledger` 服务（保持原来的 `BEANCOUNT_AI_API_KEY` 环境变量），刷新页面。Dashboard 动态发现插件，无须添加路由。

## 使用

1. 顶部「账单」列表会显示账单文件夹中的每个文件，并把对应草稿合并到同一行。没有草稿时显示「导入账单」；已有草稿时显示草稿状态、总笔数、已入账、不导入和待审核笔数，并提供「继续审核」。也可以使用列表右上角的支付宝 / 微信按钮上传新账单。支付宝入口只接受 CSV，微信入口只接受 XLSX；文件选择器和上传前检查都会限制对应扩展名。按表头识别来源，并校验所选上传入口；选错平台会提示使用正确入口。
2. 导入产生待审草稿，尚不记账。同一个文件按完整 SHA-256 恢复同一批次；如果原文件缺失，重新上传会恢复原始文件，保留已有账户选择、审核修改和 AI 结果。原始文件缺失但草稿仍存在时，草稿会保留在账单列表中并标明「原文件缺失」。从文件夹重新读取同一内容也会更新原文件关联，不覆盖其他内容的文件。
3. 筛选重复候选，取消多余记录；底部入账操作区的「批量选中」菜单可添加多条规则，每条先选择「选中」或「取消选中」，再从带复选框的下拉框勾选要匹配的交易类型。规则只作用于当前显示、未锁定、未入账的交易，只修改选中状态，不改变筛选和显示；同组可多选，任一命中即可，同一笔交易同时命中选中与取消选中时取消选中优先。规则先暂存、可逐条删除，点击「应用规则」后统一更新选中状态，并可立即撤销本次批量修改。确需保留的候选勾选「已核对」。「交易状态需人工确认」与「疑似重复」分别提供「已核对」复选框，两项核对独立保存；前者直接显示在提示列，不收进普通核对提示。选中交易须完成对应核对后才能入账，锁定、已入账及只读交易不可修改核对状态。交易状态含「成功」（例如交易成功、支付成功、充值成功、退款成功）或包含微信已完成状态「已收钱」「已存入」「已转账」「已收款」「对方已收钱」（包括「已存入零钱」）时免核验；其他状态（包括关闭、失败、待确认、已全额退款和空状态）均需人工勾选「已核对」。前端展示、筛选、导入解析、旧草稿恢复和最终入账校验共用此规则，旧草稿重新打开会更新状态提示并保留已有账户、AI 结果和核对记录。「交易关闭或失败」不再单独提示或提供筛选类型，旧提示在重新打开、保存草稿时移除，关闭和失败交易仍默认不选；如要入账，必须完成统一的状态核对。旧草稿缺少交易状态核对记录时视为未核对。提交前重新检查账本，新增重复候选必须再次审核。
   明确不需要入账的交易可先勾选，再点击「标记不导入」。该操作立即保存到草稿并锁定这些交易，将其从待审核中排除，但不会写入 Bean；需要重新审核时，在「已完成」里查看不导入记录，点击「可导入」清除标记并解锁，再用交易复选框选择是否入账。普通取消勾选仍表示尚未处理，不会自动标记为不导入。
   交易卡片用红色表示支出、绿色表示收入、蓝色表示账户流转；两个账本账户之间的同色箭头按实际账户位置指向资金去向。有明确关联信息的原支付与退款统一分组，可包含一笔原支付和多笔退款。全额匹配默认收起为灰色抽屉卡片；部分退款、金额不一致或关联不完整显示橙色的「退款不完全匹配」分组并默认展开。摘要以交易描述为主，列出原支付总额、退款总额、净支出或净流入、交易对方、支付方式及双方时间；组内保留每笔原始彩色交易和全部审核操作。表格工具条左侧提供单一搜索框，输入时实时匹配交易对方、商品、单号或金额；搜索或筛选命中一笔时保留整个关联组作为上下文，但筛选批量操作仍只处理实际命中的记录；工具条分别说明符合筛选条件的交易数量与额外展示的关联交易数量，关联行不会计入对应状态或提示类型的命中计数；默认不分页，展示筛选范围内的全部交易；需要时可点击「启用分页」，分页按卡片计数，初始每页 50 项，支持输入正整数自定义（回车或离开输入框生效）。点击「显示全部」可恢复不分页，再次启用时保留自定义数量，切换不会改变筛选或交易勾选，也不会拆开退款组。折叠表头直接为分类账户、资金账户提供排序和筛选按钮；展开态表头通过「原账单信息」的紧凑筛选按钮打开浮层，支持按选中状态、日期区间、金额、支付方式、交易对方、账户、资金流向、收/支、交易状态及审核提示组合筛选；选中状态、资金流向、收/支（包括不计收支）、交易状态与审核提示支持复选框多选，同组为任一匹配，不同组同时满足。已启用条件汇总为标签，标签右上角 × 可单独移除，标签行右侧可清除全部表头筛选。浮层在「原账单信息」入口内将「日期」「金额」「收支」「交易状态」作为顶部切换组，并在下方固定展示「交易信息」（收付款方式、交易对方）和「账户绑定」（分类账户、资金账户）。各组显示已启用条件数，切换保留输入与选择，底部「清除此列」统一清除全部条件及包含 / 排除状态，保留选中状态、审核提示列条件及搜索词。浮层标题、分组切换和底部操作固定，内容区独立滚动。「资金流向」按当前审核金额、账户和交易性质判断实际流入、流出或账户流转；两个绑定账户均为资产或负债账户时，优先归为账户流转，箭头按审核金额的正负指向。「收/支」读取文件中的原始收支标记，不随审核修改，选项仅来自本批次实际值，不预置“未注明”等账单中不存在的值。例如原账单标为「不计收支」的退款，资金流向仍可显示为收入。日期使用按天调整的双端滑块，自动取当前账单最早、最晚日期，不再显示日期输入框。金额仅提供区间滑条，按金额正负分为红色支出和绿色收入两组滑块，金额统一按正数显示，零金额归入收入一侧；各自按当前账单自动确定最小、最大值，滑条上方的区间数字可直接输入，回车或离开输入框后生效并同步滑条；输入保留两位小数，超出账单范围或另一端边界时自动限制，空值或无效输入恢复原值，Esc 取消当前数字编辑。不再提供文本包含模式或独立的最小、最大金额表单。两组独立约束对应金额，未调整的一组不限；包含 / 排除只作用于已调整的组。每组金额标题旁提供显示开关，关闭后整组变灰、滑块禁用，并排除该类全部交易；两组均关闭时显示空结果。关闭不清除已选范围，重新开启会恢复原范围，也可移除或切换对应的「排除 · 支出金额 / 收入金额」标签恢复显示；金额组的包含 / 排除不会重新引入已关闭的类型。「清除此列」和清除全部筛选会恢复两组开关。日期和金额区间均包含边界值，滑块上方显示当前范围，拖回完整范围即取消该组限制；缺少对应记录或只有一个可选值时禁用滑块。各条件组可独立切换「包含 / 排除」，排除是对该组匹配结果取反，未设置条件时不生效；条件标签用蓝色表示包含、橙色表示排除，并显示文字标记；点击标签可直接切换包含 / 排除，各组的标题与切换按钮在滚动时保持对应。「重点核对」集中显示待选账户、核对提示、退款匹配和不计收支四项，宽屏一行排列，审核区宽度不超过 1000px 时改为两列；数字与说明居中，审核视图入口及下拉选项的计数不再附加「笔」。重复候选归入核对提示类型，与其他提示和需人工核验的状态按交易去重计数，同一条交易只计一次。点击「核对提示」展开类型筛选浮层，打开本身不改变显示范围。浮层按重复候选、交易状态需人工确认、退款相关、不计收支、零金额交易、待选实际资金账户、缺少交易单号七类显示当前「排除已完成」范围内的全批次数量，无记录的类型置灰。类型支持多选，任一类型匹配即可；同一笔可能属于多类，结果不重复。可通过「全部提示」恢复全部有提示交易，取消最后一个类型也恢复全部提示；可与搜索、表头条件组合，退款组保留完整上下文。关闭浮层保留筛选，重置视图或重新打开批次会清除类型筛选，不修改勾选或核对状态；不计收支按原账单标记统计，不随审核金额或账户修改而变化。「退款匹配」合并为一个下拉，提供全部退款、全额退款匹配和退款不完全匹配，计数覆盖关联组内的实际交易；可随审核金额修改即时更新。「核对提示 → 交易状态需人工确认」筛选需人工核验的原始交易状态，排除含「成功」和微信已完成状态，勾选已核对后仍保留在该状态筛选结果内；不再提供判断等价的「非成功交易」独立入口。点击各项可集中筛选，并与搜索和表头条件叠加；表头审核筛选和批量选中规则使用同一分类。计数按关联组内的实际笔数计算；修改审核金额后，匹配状态、摘要及计数同步更新。缺少关联原交易或尚未匹配的退款继续列入不完全匹配，未关联的普通交易不会按商家名称强行分组。
4. 点击「原账单信息」表头的筛选按钮，可在顶部切换日期、金额、收支与交易状态，并直接使用下方固定的「交易信息」和「账户绑定」区域：前者筛选收付款方式与交易对方，后者筛选分类账户与资金账户；交易对方类型可选择「全部」跨类型查看。分类账户和资金账户的候选只列当前批次实际绑定的账户，并提供「未绑定」。收付款方式、交易对方、分类账户、资金账户及交易状态条件均复用「包含 / 排除」控件，同组多选为任一匹配，排除时同时排除选中的项目；交易对方排除仅作用于所选收支类型中的选中商家。选项在筛选浮层内展开，已启用条件显示在表格上方，点击标签可切换包含 / 排除，也可单独移除或通过「清除此列」「清除表头筛选」清除。这些条件可以与搜索、交易状态及其他表头条件组合，只改变显示范围，不修改账户关联和审核草稿。点击「本次入账」中的「账户设置与 AI 分类」，可按交易对方、收/付款方式或交易内容保存长期账户关联，输入规则时实时预览匹配项和笔数。账户关联中切换收支类型会保留交易对方搜索词；选择「全部」且使用按交易对方选择时，保存会按实际类型拆成多条规则，推荐账户类别不一致时只提示并仍可保存，适合退款冲销等跨类别处理。交易对方自定义正则规则仍只作用于一个明确的收支类型。账户浏览器可以独立创建新账户，不需要先选定匹配对象：展开创建区、填写账户名称和开户日期后点击「确定」，账户会写入账本并立即出现在选择列表中，随后由用户选择账户并保存关联。账户浏览在搜索框下列出可用的根类别按钮；进入类别后显示面包屑，按「根账户 / 父账户 / …」逐层返回。搜索会跨全部层级和当前可用根类别返回完整账户路径，清空搜索后恢复当前层级浏览。账户使用紧凑单行列表，默认启用「展开 / 智能」：当前层只有一个账户时继续向下展开，遇到同级多个账户时停止；也可切换到「全部」递归展开整个分支。父账户行按约 70% / 30% 分区，前 70% 只折叠或展开，后 30% 才进入该账户层级；关闭开关会收起已展开子账户。每个账户行末尾悬停时显示「+」，点击后在该行下方展开子账户名称和开户日期编辑区。多选列表可用「全选 / 取消全选」处理当前搜索结果。页面上方「账户关联管理」汇总、搜索和管理已保存规则。规则写入 `plugins/payments/config.json`，以后导入时自动复用。也可手动分类，或通过「账户设置与 AI 分类」准备并确认分类。可保存草稿后离开，重新打开继续处理。
   点击每笔交易的缴费方式，打开「缴费方式与账户」面板：选择已有资产 / 负债账户，或在账户浏览器中创建 CNY 账户。账单未提供缴费方式时显示「未注明缴费方式」，它同样是一种可单独筛选、勾选和绑定的方式。例如进入 Assets 后，在 Assets:Bank 行末尾点击「+」，即可在该行下方创建 Assets:Bank:Wallet；子账户名还可用冒号一次创建多级路径，例如输入 Wallet:Travel 会创建 Assets:Bank:Wallet:Travel。创建只写入账户定义，不会自动修改缴费方式关联或当前交易；账户列表更新后，手动选择新账户并点击「保存关联」才会绑定。可以同时勾选多种缴费方式指向同一账户；微信和支付宝分别记录关联。同批次未锁定、未入账的对应交易（含未选中的交易）会更新资金账户并保存当前草稿和 AI 结果。01 选择收/付款方式或填写自定义正则后，可在 02 继续按商品说明收窄匹配；留空表示只按方式匹配，填写后两个条件默认同时命中（AND）。02 的候选摘要仅来自 01 当前方式范围，使用固定三行高度的独立滚动区；目标资金账户位于 03。同一方式可按不同商品说明分别关联资金账户，有商品说明的规则优先于基础规则。以后导入自动使用关联；旧草稿仅补齐空缺资金账户，保留人工选定的账户。重新关联只替换规则身份完全相同的旧关联，基础规则与商品说明规则可以同时保留。
5. 账户关联统一为「01 选择匹配依据 → 02 选择账户」。第一步可选择交易对方、收/付款方式或交易内容；点击交易对方或收/付款方式会预选对应对象，点击交易内容会预填该笔摘要。交易对方和收/付款方式支持精确多选或自定义正则；交易内容支持包含或正则匹配，可独立匹配，也可用交易对方或收/付款方式限制范围，范围与内容条件必须同时命中。交易对方、收/付款方式和交易内容候选均使用约三行高度的独立滚动区，交易对方列表打开时滚动到已选对象。商品说明输入会实时过滤交易内容候选，显示命中条数与总条数，并更新交易笔数；点击候选会填入包含条件。交易对方正则只检查名称，商品说明条件只检查摘要，均使用 JavaScript `RegExp(pattern, "u")` 并清理字段开头的 BOM 和首尾空白。当前收支类型没有命中时，会提示其他类型的命中数量。同一商户的默认账户与多个商品说明例外可以共存，也可保存不指定商户的内容规则。默认内容规则先匹配，新建的交易对方、收/付款方式基础规则位于内容规则之后；手动排序后按保存的优先级匹配。

   第二步选择目标账户。按收/付款方式匹配或用其限制内容范围时，关联资产或负债资金账户；其余模式关联分类账户。普通支出通常推荐 Expenses，收入通常推荐 Income，转账和账户流转通常推荐 Assets / Liabilities；分类账户浏览器列出全部五类根账户，非推荐类别仅提示，仍可保存。选择「全部」收支类型时会按实际类型拆分规则。原始名字、备注和支付方式原样保留，分类账户关联不会替换资金账户。交易内容末尾的「原始交易信息」按钮用于查看全部原始字段，与内容关联入口分别操作。

   「账户关联管理」支持按账户查看及调整优先级。按账户查看提供可多选的类别标签，依次为资产、负债、收入、支出、权益，并以不同颜色标识；点击「全部」或取消最后一个标签恢复全部账户。每张账户卡片可删除其中一条规则，也可删除整组关联；交易对方、收/付款方式和交易内容分别使用紫、蓝、橙色。优先级视图支持拖动及上下按钮，数字越小越先匹配，调整后自动保存；搜索只改变显示范围，排序仍保存全部规则。资金账户与分类账户分别采用各自第一条命中的规则。当前可编辑批次会按新顺序重新匹配，保留已锁定及已入账记录。
   “包含”模式将“闲鱼 / 咸鱼 / 閒魚”视为同一词；“正则”模式仍按原表达式严格匹配。
   账户关联主面板、分类账户和资金账户浏览弹窗均支持按 Esc 关闭；存在嵌套菜单时先关闭当前层，再次按 Esc 关闭主面板。

6. 草稿支持「锁定草稿 / 解锁草稿」；行内通过「不导入 / 可导入」同时管理标记与锁定状态，不再单独提供锁定按钮。锁定保存当前审核状态，并排除该行后续编辑、批量操作和 AI 请求；恢复可导入后可继续审核。
   待审草稿可在「账单」列表或当前草稿顶部删除，需确认后执行。删除移除审核内容和 AI 结果，保留原始账单文件；原文件已缺失时也可删除。已有入账记录的批次显示灰色禁用删除按钮，悬停时提示“已有入账记录，不能删除草稿”，后端也会拒绝删除；版本变化时需刷新后重试。
7. 核对交易后点击「确认入账」，再确认写入 Bean。只锁定实际写入的行，未入账的其余行可继续选择、分类和入账，后续内容追加到同一 Bean 文件。已入账行不能通过解锁再次导入；旧版部分入账批次按 Bean 的 import-batch / import-line 元数据恢复。
   当草稿中的每一笔都已入账或标记为不导入时，账单列表显示「已全部入账」「已全部标记不导入」或「已全部处理」，不再显示「待审核」。

当前审核批次下方集中显示原始账单路径、Bean 输出路径（已有输出时）和记录笔数；主流程、重点核对、已完成和重置视图集中放在「交易审核」标题下方，组成同一个审核筛选区；三组宽屏并排、窄屏整组换行，数字居中，重点核对保留更宽空间。主流程提供全部、已选中和待审核筛选，重置视图统一清除显示筛选并恢复「排除已完成」开启，但不改变交易勾选，不再额外显示「下一步」卡片。「本次入账」固定悬浮在视口底部，始终提供保存草稿、AI 分类、批量选中、不导入和入账操作；宽度跟随审核区，左侧为本次勾选数量及紧跟其后的「查看」「清空」按钮：查看会清除其他筛选并定位到全部待入账勾选项目，清空作用于全批次待入账勾选、不受当前筛选或分页影响，可使用「撤销」恢复，不修改账户、核对状态或不导入标记，锁定、已入账和只读记录不可修改；左侧不再重复显示缺账户或待核对提醒，中间的本批次进度条与已处理笔数填满可用宽度，与两侧保持间距，右侧为操作按钮；进度不重复显示百分比。按审核区实际宽度自动压缩或换行，并按实际高度预留底部空间。最终入账确认也在悬浮栏中展开，确认写入后才记账。「审核规则与提示」使用「本次入账」标题后的小问号入口，不占用额外一行，也不显示底部进度百分比；右侧操作按钮保持垂直居中。问号默认淡化，悬停、键盘聚焦或展开时恢复清晰；点击向上展开、再次点击或按 Esc 收起，锁定说明收在规则内容中。

「已完成」分组内提供默认开启的「排除已完成」开关，排除已入账和不导入的交易，同时更新重点核对各项及类型下拉的数量与下方表格；单独锁定的未完成交易不会因此隐藏。退款分组内也排除已完成明细，原始匹配结果与金额摘要仍以完整关联组计算，并标明隐藏数量。关闭开关可查看完整批次；点击「已入账」「不导入」分类时临时关闭排除以查看对应历史记录，不覆盖其他审核面板记住的开关偏好；离开已完成分类后恢复上次的开启或关闭状态，初始默认开启。在已完成分类中主动开启排除会返回全部未完成交易。切换只改变显示，不修改勾选、账户或审核记录。

入账操作区右侧保留「请补齐 xx 笔账户」及其「一键查看」、以及「xx 笔待核对确认」及其「一键查看」「一键核对」合并在同一行，按钮紧跟各自提示。笔数按已选中、未锁定且未入账交易中的待确认项去重统计，疑似重复与交易状态均待核对时同一笔只计一次。「一键查看」清除搜索、表头和提示类型条件，集中显示这些交易，并保留退款组上下文；「一键核对」只勾选这些交易实际需要的核对项，不修改未选中、不导入、锁定或已入账记录，也不自动保存或入账。缺少账户单独提示，完成核对后仍须补齐账户才能入账。

「原账单信息」筛选卡独立提供「交易状态」，选项来自本批次实际解析值，兼容微信「当前状态」和支付宝「交易状态」。原始元数据筛选仅保留单独的「交易状态」和「收支」组中的「收/支」，移除通用字段添加、任意字段值和关键词筛选。两项均支持多选及包含 / 排除，可通过条件标签单独切换或移除；清除此列、清除表头筛选、重置视图及切换批次均清除对应条件，筛选不产生草稿修改，也可在只读或锁定状态下使用。命中退款组中的一笔时保留关联上下文，批量操作仍只作用于实际命中的交易。微信「支付方式」、支付宝「收/付款方式」及「收付款方式」统一显示为「收付款方式」；原始文件、原始字段名与值保留在原账单和审核草稿中，不再写入 Bean 的 payment-\* 元数据。已有收付款方式及交易对方快捷筛选继续使用与账户关联相同的解析值。其他原始字段仍可通过每笔交易的「原始交易信息」完整查看。

「重点核对」的待选账户笔数按全批次缺少资金或分类账户的交易统计，不受勾选、搜索或表头条件影响，包含未选中和未完成的锁定记录，并遵循「排除已完成」开关；点击后使用同一缺账户条件筛选，退款关联组仍保留上下文。「本次入账」的缺账户笔数只检查已选中、未锁定且未入账交易，未选中交易缺账户不会阻止入账；其「一键查看」清除其他条件并只显示本次需要补齐的记录，与全批次入口分别标识当前筛选。

## 存放位置

审核表默认折叠，展开前后都使用同一套折叠专用表头，不再切换表头或改变导航工具条。折叠表头使用不含行号的网格，分别展示复选框、金额 / 日期、状态 / 分类、交易对方、分类账户、可选收付款方式、资金账户和交易内容。点击卡片任意非控件区域可展开，点击交易标题打开内容匹配关联，标题末尾另有带文档图标的「原始交易信息」按钮；标题后的空白仍由卡片接管展开。金额 / 日期与状态 / 分类分别提供即时筛选；交易对方、分类账户、收付款方式、资金账户各自提供升序、降序和恢复账单顺序按钮，筛选使用当前批次值并支持多选、搜索及包含 / 排除。选中状态、审核提示仍可从同一表头打开，完整筛选入口保留在「原账单信息」图标中。日期放在金额下方并以灰色小字显示；原始「收/支」与实际流向不同时，以较淡小字补充原始标记。窄屏或长收支值自然换行，不增加竖向分隔线。

展开态的交易与账户区域使用「原账单信息」表头，分类账户、资金账户筛选归入「账户绑定」区域。交易描述作为跨两列的主标题，点击可按该笔内容关联账户，标题后保留 ↗；无描述时使用交易对方，均为空时显示「未注明交易内容」，没有摘要时不提供内容关联。账户框内保留「交易对方」及收付款方式两个标签：资金流入显示「收款方式」，资金流出显示「支付方式」，账户流转也按实际流入或流出显示，修改审核金额后同步切换。每一行右侧紧跟绑定账户，账户选择器保留完整无障碍名称及编辑、绑定、创建操作。两排共用左右网格，长主标题或交易对方不会挤乱支付方式和资金账户的对应关系；主标题最多显示两行，悬停或打开原始信息可查看全文。

左侧选择和操作列固定为 72px；原账单信息内容区最大 720px，另预留两侧共 24px 内边距；右侧提示列至少保留 196px，并承接剩余宽度。表格铺满审核区，最低 800px，行底色与横线延伸到最右侧，滚动条位于审核区最右端。提示文字最大宽度为 360px，紧接交易区域靠左显示；窄屏在表格容器内横向滚动，退款组内表格随抽屉宽度收缩。交易对方、收付款方式及绑定账户整合为最大宽度 720px 的圆角区域，使用随交易类型变化的浅色底与细边框，仅以横线分开上下两组。左侧原信息填充可用宽度，右侧账户宽度最多 300px，表头与区域内的内容同步对齐；「不导入」条目也保留账户外框，清空、浏览和创建入口使用较轻的样式，行内操作采用紧凑按钮。

审核金额位于交易标题行最右侧，仍可直接编辑，不在日期列重复显示。金额使用 18px 等宽数字，支出红色、收入绿色、账户流转蓝色，流入金额补充 +，币种 CNY 使用紧随数字的 9px 小字；输入宽度随内容变化。两个账本账户之间显示带颜色的箭头，靠左对齐账户名称：上方是交易对方绑定账户，下方是收付款方式绑定资金账户。支出显示红色 ↑，收入或退款显示绿色 ↓，账户流转为蓝色并按实际方向切换。箭头使用 40px 高的独立连接行，遮罩与账户外框留出间距，不占用原信息或账户控件；修改审核金额后方向同步更新。折叠态在金额 / 日期右侧显示交易状态和交易类型；展开态在交易标题后用紧凑标签显示原账单分类，分类为空时不占位。正常状态使用浅绿色，需人工核验使用浅橙色，空状态显示「状态未注明」。

是否纳入入账通过左侧复选框控制，不再显示右侧「待选择 / 已纳入」及「纳入入账 / 取消纳入」。复选框与行号下方保留宽 52px、最小高度 24px 的导入状态按钮。可审核时显示「不导入」，点击后取消勾选、标记不导入并锁定；随后显示「可导入」，点击清除标记并解锁，恢复后仍保持未勾选。两个方向都立即保存，保留账户、审核金额和核对结果；旧版单独锁定的交易也可通过「可导入」解锁。整个草稿锁定或只读时禁用，已入账行保持锁定且不显示按钮。AI 建议、退款关联、重复提醒和核对提示仍放在「提示 / 操作」列，普通核对提示默认展开并显示条数，可手动收起，疑似重复确认操作保持可见。账户突出末级名称，下方显示父级路径，悬停查看完整路径，账户选择支持键盘操作。

点击「原始交易信息」按钮，在独立宽面板中按原表列顺序查看全部字段，包括备注、商户单号、额外列及空值。重复列名不会覆盖，长单号和多行内容不截断；只读、已锁定及已入账交易也可查看。面板可通过外侧空白、关闭按钮或 Esc 关闭，并返回查看入口；在面板内选择文字后拖到外侧不会误关。原始值独立于审核金额和账户修改保存，旧草稿打开时从经过 SHA-256 校验的原始文件补齐，不覆盖人工审核或 AI 结果。

「账户绑定」中的「分类账户」「资金账户」只列当前批次实际绑定的账户，并分别提供「未绑定」选项，可搜索、多选、全选和清空。分类账户精确匹配每笔交易的分类侧绑定账户，资金账户精确匹配收付款方式绑定的资金侧账户；同组任一账户匹配即可，两组同时满足，包含 / 排除和条件标签各自独立，不会将父账户或另一侧的同名账户当成命中。搜索只查找候选账户，不直接改变交易显示范围；筛选在只读或锁定状态下同样可用，不修改绑定、勾选或草稿。筛选内容留出完整的边框空间，键盘焦点轮廓显示在控件内侧。

账户选择浮层桌面宽度为 320–360px，随触发框宽度调整，高度随内容增长并受 420px 和可用视口空间限制；紧贴实际账户框，预留 8px 间距，必要时向上展开并避开左右边界。滚动、窗口尺寸或浮层内容尺寸变化时更新位置；窄屏贴合视口左右留白。浮层使用页面顶层显示，避免审核区动画和表格裁切影响定位；账户路径在打开、切换层级、退出搜索及宽度变化时自动滚动到最右侧，优先显示当前层级与创建按钮，同时保留向左查看父级的操作；账户列表独立滚动，搜索与底部操作保持可见。打开时先进入页面顶层再定位，聚焦及关闭返回入口均不触发页面滚动；内部列表和路径滚动不重新定位整个浮层，页面或审核区滚动时仍跟随入口。内嵌筛选菜单保持文档布局，新建账户仅在内部列表定位，避免带动外层页面。

交易行保留支出淡红、收入淡绿、账户流转淡蓝的整行底色，配合同色左侧细线和箭头；选中、悬停时略微加深底色，仍保持原交易类型的颜色。

完整审核表头中的交易搜索框位于「提示 / 操作」列最右侧，折叠表头则放在「交易内容」列最右侧；两种表头都保留当前显示交易的全选入口，标题和筛选按钮保持靠左，与列表一起保持可见；空间不足时在同一表头内换行，不拉长原账单信息列。搜索范围及即时筛选行为保持不变。

「保存审核草稿」仅在审核数据有未保存修改时可点击；没有修改或已改回保存时的内容，显示灰色禁用的「已保存审核草稿」。搜索、筛选和翻页不会触发待保存状态。保存过程中显示「保存中…」并禁止重复点击，成功后恢复已保存状态；失败时保留修改，可再次保存。

- 原始账单：`import_data/`。读取已有文件保持原路径；上传按内容归档到 `import_data/WeChatPay/<摘要>-<原名>` 或 `import_data/AliPay/<摘要>-<原名>`，保留完整原始字节。
- 审核草稿与 AI 结果：`plugins/payments/drafts/<SHA256>.json`。包括选中状态、资金账户、分类、置信度和分析理由。点击「保存审核草稿」时通过通用仓库写入事务只提交对应的草稿文件，不会带入工作区内其他改动。
- 交易对方与交易内容关联：`plugins/payments/config.json` 的 `counterpartyAccounts` 保存 `provider`、`kind`（转账收入 / 转账支出 / 普通收入 / 普通支出 / 流转）和 `account`。可选的 `match`（`exact` / `regex`）与 `pattern` 表示交易对方条件；可选的 `description` 表示商品说明条件，格式为 `{ "match": "contains" | "regex", "pattern": "…" }`。至少提供交易对方或商品说明之一；仅商品说明的规则不保存空的交易对方条件。两者都有时必须同时命中。同一商户的基础规则和不同内容例外可独立更新、删除。非法正则不会写入配置；已锁定及已入账行不会被规则修改。
- 收/付款方式关联：同一配置的 `paymentAccounts` 中每项包括 `provider`（`wechat` / `alipay`）、`payment`（原始方式文字或正则表达式；未注明时为 `""`）、`match`（可省略，默认为 `exact`；自定义匹配为 `regex`）、可选 `description`（格式同交易对方规则）和 `account`。存在 `description` 时必须同时命中收/付款方式与商品说明；同一方式可以保存基础规则和多个内容例外。规则按平台和完整匹配条件识别，相同条件更新账户，不覆盖其他内容规则。一个账户可以出现在多项中；银行卡或组合支付仍需人工核实实际资金账户。
- 两类规则均可保存整数 `priority`，数字越小越先匹配。没有手动顺序时，所有带商品说明的规则默认位于基础规则之前；已有手动顺序时，新基础规则追加在末尾，新内容规则默认放在前面，更新已有规则保留其优先级。管理面板拖动排序会保存全部规则的优先级，允许基础规则手动移到内容规则之前；重新打开及导入新账单均复用保存的顺序。
- 面板或账户关联管理新建账户：写入 `plugins.payments.account_file` 指定的文件，默认 `accounts/payments.bean`。插件不再创建或修改 `accounts/index.bean`；账户文件尚未被入口 Bean 直接或间接引入时，会向入口追加指向该文件的 include。新账户名由所选父账户和多级子账户路径组成，开户日期默认取当前批次最早交易日，币种为 CNY。独立的 `create-account` 操作只原子写入账户定义和必要的 include，不修改配置或当前草稿；后续绑定仍通过关联操作完成。配置和草稿均检查版本冲突。关联已有账户不会改写账户定义。
- 转换结果：`transaction/imported/<批次最早交易日期>-<来源>-<批次摘要>.bean`，例如 `2026-10-01-wechat-<摘要>.bean`，文件名按年月日自然排序，与原文件分开。每笔仅写入 `import-source`、`import-line` 和 `import-batch` 三项导入元数据，不写入任何 `payment-*` 字段；单号、原时间、状态、收付款方式等完整信息仍保存在原账单和审核草稿中。已有 Bean 不自动改写。使用现有 include 通配符；没有覆盖输出时自动加入显式 include。

原文件移动子目录后，按完整 SHA-256 定位当前账单文件；同名但内容不同的文件不会被接受。已生成 Bean 中的原始导入位置保留以供追溯。

路径可在 `benacount-local.yaml` 配置，必须是互不嵌套的账本相对目录：

```yaml
plugins:
  payments:
    enabled: true
    input_dir: import_data
    output_dir: transaction/imported
    account_file: accounts/payments.bean
navigation:
  routes:
    payments:
      group: plugins
      position: first
      quick_menu: true
```

`account_file` 必须是以 `.bean` 结尾的账本相对路径，默认为 `accounts/payments.bean`。该文件可以位于任意账本子目录；未出现在入口 Bean 的 include 链中时，创建账户会自动补上直接 include。

## 解析与记账约定

- 支付宝交易明细只支持 CSV（UTF-8 / GB18030），微信支付只支持 XLSX。ExcelJS 负责 XLSX 容器解析。旧版二进制 `.xls` 请另存为 `.xlsx`。单文件最大 20 MB、25000 行；金额使用十进制字符串和 BigNumber，避免浮点误差。
- 收入在资金账户记正数，支出记负数；另一方记相反金额，币种为 CNY。可以手动改金额，包括「不计收支」的方向。
- 新导入交易的分类账户保持为空，不自动选择 `Expenses:Other` 或 `Income:Other`。命中已保存的交易对方关联规则时仍使用关联账户；其他交易由用户手动选择或通过 AI 分类。旧草稿与已入账记录不批量清空，手动或关联规则明确设置的「其他」账户仍保留。
- 关闭 / 失败、退款相关、不计收支、零金额交易默认不选。退款自动按订单号、商户单号，或已退还状态、金额、交易对方和时间关联原支出；两侧默认不选，关联交易按组显示，完整且金额相抵的退款组收起为灰色卡片，不完全匹配的退款组默认展开并显示净差额；内部保留原有颜色标记及关联行号。支付宝「不计收支」的退款按资金流入显示。部分退款单独提示，需人工核对净额；对应关系不明确时不强行配对。支持同一原订单的多笔有明确单号的退款。退款不自动冲销或合成新交易，人工调整和已有 AI 分析会保留；已有未入账草稿在重新打开时应用配对规则。
- 只有明确标注「零钱 / 账户余额 / 余额」的记录自动映射对应钱包。未匹配到账户的银行卡、余额宝等支付方式需选择实际资金账户。每行按原账单单笔交易处理，保留原始金额；不会因为支付方式中含有 &、＆ 或优惠字样而提示拆分，旧草稿重新打开时也会移除这条已停用提示。
- 重复候选依据来源和单号，或同日同金额并且交易对方 / 描述相同，覆盖当前批次及已包含的账本源文件。新生成的 Bean 通过导入批次和行号关联审核草稿中的来源与单号，旧记录仍兼容读取 payment-provider / payment-order-id；草稿缺失或损坏时仍可按同日同金额等条件检查。不会自动删除历史账本记录，人工决定本次保留哪些记录。
- 入账验证交易日账户是否开放、币种是否可用以及是否产生新账本错误。批次、输出 Bean、必要的 include 更新通过现有仓库事务和 Git 写入机制一同保存，并检查草稿及原文件版本。

## AI 复用

通过宿主注入的 `LocalAiService.categorizeTransactions` 和本地 AI 配置执行后台任务，不新增密钥或供应商配置。只向现有 AI 服务发送已选交易的日期、对方、摘要和金额，候选账户仍由当前账本提供。

AI 返回 `Expenses:Other` 或 `Income:Other` 时直接采用并保存原始置信度和分析，但仍计入「失败 / 无有效分类」，不计入有效分类成功数。没有结果、账户无效或 AI 请求失败时，按资金流入 / 流出使用交易日可用的 `Income:Other` / `Expenses:Other` 兜底，保存置信度、原建议与原因；没有 AI 结果时置信度为 0，并明确注明请求失败或未返回结果，不伪造 AI 分析。交易提示列显示「AI 兜底」及说明，草稿保存 `aiFallback` 标记；重新打开会保留且不重复发送已有分析。手动修改分类或重新关联商家账户时清除旧 AI 说明和兜底标记。若账本没有对应的可用账户则不新建，提示手动选择；保存失败不冒充已分配成功。导入本身仍不预填分类账户。

「成功并保存」「失败 / 无有效分类」「未处理」三项均提供「一键查看」，清除搜索、表头和提示类型条件后，在交易表中仅显示对应结果，退款关联上下文仍保留。无有效分类中另提供「查看明细」，展示本次交易的原行号、日期、对方、描述、金额、执行前分类账户、保存后的兜底账户、AI 返回账户与说明（如有），以及具体原因。成功交易不会混入无有效分类明细，尚未执行的后续批次也不计作失败。进度、逐行明细、兜底标记与分析均保存在批次草稿，不新增 Bean 元数据。只有尚未分配或尚未处理的交易提供重试，已保存的“其他”分析不重复调用。

「重点核对」提供「AI 分类」下拉框，可筛选「AI 已设置账户」「无法分类 / 失败（含其他）」「尚未 AI 分类」。计数来自当前批次已保存的 AI 结果和失败记录，人工绑定的具体账户不混入 AI 成功，其他兜底仍归入无法分类；不改变勾选状态，退款关联上下文保留，刷新后仍可使用。

仅处理已勾选、可编辑、未入账、未标记不导入，且尚无 AI 分析、分类账户为空或仍为 `Expenses:Other` / `Income:Other` 的交易。「本次入账」常规操作区提供白色的「账户设置与 AI 分类」通用按钮，不再提供「AI 一键设置」或「AI 分类已选交易」按钮；页面顶部不再单独展示「统一关联账户」区域，手动关联入口统一保留在准备弹窗内。没有勾选交易或待分类交易时，仍可打开弹窗手动关联账户，但不能开始 AI 分类；只读或锁定草稿时禁用入口。已有具体分类不会覆盖，收付款资金账户仍需手动选择。

点击「账户设置与 AI 分类」只打开准备弹窗，不立即请求 AI。弹窗提供交易对方、收/付款方式和交易内容三个关联入口；交易内容可独立匹配，或按交易对方、收/付款方式限制范围。保存或取消关联后回到准备弹窗，剩余需 AI 分类及跳过的数量实时更新。全部手动绑定后禁用开始按钮，不产生 AI 请求。仅点击「开始 AI 分类」后，才按最新的交易状态筛选并发送剩余候选。

准备与进度窗口仅在打开对应审核批次后显示，进入账单列表时不会自动打开历史批次或弹出进度。窗口使用固定在视口中央的非模态浮层，不锁定背景；鼠标移到窗口外可继续滚动页面或交易列表，滚动不会关闭窗口。鼠标在窗口内时独立滚动，不串到背景。准备状态可在背景直接调整勾选，待分类数量同步更新；关闭按钮或窗口内按 Esc 返回审核入口且不改变滚动位置。进度窗口在运行中和完成后均可点击「缩小」或点击窗口外部折为右侧悬浮进度卡，不中断后台分类；窗口内点击、文字选择拖动和背景滚动不会触发缩小。悬浮卡持续显示批次、已处理及成功失败数量，点击即可展开。任务结束后点击关闭按钮或按 Esc 也仅缩小，只有点击「完成」才彻底移除窗口及悬浮卡；已完成进度不在下次打开审核时自动弹出。只有运行中的展开 / 缩小偏好按账本记录批次标识，任务结束即清除，不在浏览器存储交易明细。逐笔分类结果、AI 分析和重点核对筛选仍保留。手动账户关联继续使用独立对话框。

准备弹窗、账户关联表单与 AI 进度独立更新。打开、关闭、搜索、勾选关联对象和切换目标账户都不触发底层交易表格重新渲染；真正保存关联或修改交易后才同步更新。账户层级选项按账本账户缓存，商家及其收支类型、已有规则由一次交易扫描建立索引，避免对每个商家重复扫描整张账单。准备弹窗只提供关联入口，不提前初始化关联表单；手动绑定实际变化时，仍同步更新待分类数量。

每批最多 50 笔由服务端顺序处理并保存结果；启动前先持久化审核修改、任务标识及候选列表，浏览器仅轮询进度。缩小、刷新或关闭页面都不会取消后台任务，重新打开对应审核批次后恢复进行中的进度；再次启动同一任务不会重复调用 AI。服务重启后重新打开批次会从上次已保存的批次继续。AI 等待不占用账本写锁，每批保存使用原有账本事务；分类期间拒绝编辑、锁定或删除同一草稿，避免覆盖正在保存的结果。进度面板显示实际需分类、跳过、当前批次、已处理、成功并保存、失败或无有效分类、未处理的数量；运行时持续显示转圈动画，只有保存成功才计为成功。中途请求或保存失败会停止后续批次并保留此前已保存分析；「重试未完成分类」返回准备状态，可先手动绑定，再点击开始。不会自动入账。重新打开文件或点击 AI 分类时，已有 AI 结果及人工选择的具体分类会复用，不重复请求。人工改分类会清除该行旧 AI 说明。不同账单文件不会只按商户强行套用旧分类。

## 交易折叠

交易详情默认折叠。折叠行不显示行号和展开箭头，按复选框、只读金额与灰色日期、交易状态与交易类型、交易对方与分类账户、可选收付款方式与资金账户、交易内容排列；金额始终可见并右对齐，继续显示正负号与币种。整张卡片除金额编辑、账户选择、复选框、交易标题和操作按钮等控件外均可点击展开，展开后再次点击任意非控件区域可折叠；点击交易标题打开预填摘要的内容关联页，标题末尾的「原始交易信息」按钮查看原始字段。行内文字支持鼠标拖动选择；拖选过程不会触发卡片展开、折叠或打开账户面板。交易对方、分类账户与资金账户都使用链接式入口，悬停显示下划线，不显示行内 `+`；账户文字按内容自适应宽度，点击可打开与展开态相同的关联或账户选择入口。折叠表头中的金额 / 日期和状态 / 分类分别可筛选；交易对方、分类账户、收付款方式与资金账户各自拥有独立的升序、降序、恢复账单顺序按钮和使用当前批次实际值的筛选按钮，并保留当前显示交易的全选和搜索入口；工具区在筛选图标前显示「交易内容」「审核提示」文字标签。两组账户列共用同一套列宽，切换「显示收付款账户」时表头与交易行同步增减该列；该开关默认开启，用户关闭后会按账本写入浏览器存储，展开偏好也会保存并在刷新或重新打开后恢复。退款抽屉复用同一套静态折叠表头，只保留列名，不重复提供筛选、排序、搜索或全选。提示及「不导入」等完整审核操作仍只在展开后显示，金额也在展开后恢复编辑。切换折叠或账户列不改变筛选、勾选或审核状态。

## 模块布局

`backend.ts` 仅分发操作，`backend/` 分开处理文件解析、退款、查重、账户配置、草稿生命周期和入账；`frontend.tsx` 组合页面，`frontend/` 分离状态逻辑、支付数据适配、账户面板、交易表格和样式。`types.ts` 与 `account-scope.ts` 共用类型及账户匹配规则。层级账户选择器及其样式位于 `plugins/shared/frontend/`，通过宿主的 `@plugins/shared/` 受控别名复用；支付插件只负责把账本账户转换为可选项、限定资金账户为资产 / 负债，并为非推荐的分类账户显示提示。其他插件也不能绕过该共享目录读取任意文件或通过符号链接引用依赖。

草稿、配置和 Bean 的保存统一经过 repository 的 `writeFile` / `writeFiles` 等写事务。写入成功后，底层会自动按本次涉及的路径提交 Git（账本本身是仓库或嵌套在外层仓库均可），并可通过 `commitMessage` 提供提交说明；插件业务代码不单独实现提交。
